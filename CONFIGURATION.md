# Configuration Reference

## How configuration flows

Most Project Reclaimer settings are controlled through its own documented
`RECLAIMER_DEDICATED_*` environment variables, which **override**
`dedicated.toml` at startup (upstream's own documented mechanism — see
[Environment variables](https://projectreclaimer.dev/host#config)). This
egg's [`docker/entrypoint.sh`](docker/entrypoint.sh) translates the egg
variables below into those environment variables every time the container
starts.

Two settings — a server's `name` and `port` — have **no** environment
variable override upstream, so [`docker/configure.py`](docker/configure.py)
writes them directly into `dedicated.toml`, but only inside a clearly
marked block:

```toml
# >>> PTERODACTYL MANAGED SERVER BLOCK (generated by configure.py; edits here are overwritten on every start) >>>
[[server]]
name = "..."
port = ...
# <<< PTERODACTYL MANAGED SERVER BLOCK <<<
```

**Everything outside that block is yours.** Edit `dedicated.toml` by hand
(via SFTP or the File Manager) for anything not covered by an egg variable
— custom `admins`, `[rcon]`/`[master]` tuning beyond what's exposed, etc.
Your edits are preserved across restarts and reinstalls.

## Egg variables

| Variable | Env var | Default | Maps to |
| --- | --- | --- | --- |
| Server Name | `SERVER_NAME` | `My Project Reclaimer Server` | `dedicated.toml` `[[server]].name` |
| Community Name | `HOST_NAME` | *(blank)* | `RECLAIMER_DEDICATED_HOST_NAME` (`host_name`) |
| Max Players | `MAX_PLAYERS` | `16` | `RECLAIMER_DEDICATED_MAX_PLAYERS` |
| Min Players | `MIN_PLAYERS` | `1` | `RECLAIMER_DEDICATED_MIN_PLAYERS` |
| Server Password | `SERVER_PASSWORD` | *(blank = open)* | `RECLAIMER_DEDICATED_PASSWORD` |
| Publicly Listed | `SERVER_PUBLIC` | `true` | `RECLAIMER_DEDICATED_HIDDEN` (inverted) |
| Playlist | `PLAYLIST` | *(blank)* | `dedicated.toml` `[[server]].playlist` |
| Map | `MAP` | *(blank)* | `dedicated.toml` `[[server]].map` (only if Playlist blank) |
| Game Type | `GAME_TYPE` | *(blank)* | `dedicated.toml` `[[server]].game` (only if Playlist blank) |
| Automatic Updates | `AUTO_UPDATE` | `false` | `RECLAIMER_DEDICATED_AUTO_UPDATE` |
| Enable RCON | `RCON_ENABLED` | `false` | gates whether RCON Password is passed through at all |
| RCON Password | `RCON_PASSWORD` | *(blank = disabled)* | `RECLAIMER_DEDICATED_RCON_PASSWORD` |
| Anti-Cheat | `ANTI_CHEAT` | `enforce` | `RECLAIMER_DEDICATED_ANTI_CHEAT` |
| Block VPN / Proxy | `BLOCK_VPN` | `true` | `RECLAIMER_DEDICATED_BLOCK_VPN` |

Pterodactyl's built-in `SERVER_PORT` (your assigned allocation) is used
directly for `[[server]].port`; there is no separate egg variable for it.

### Deliberately omitted variables

- **RCON Port** — not exposed. Upstream documents the console as listening
  on the *same* TCP port number as the game by default
  (`rcon_port` defaults to the game port), which is exactly what this egg
  relies on so only one Pterodactyl allocation is needed. Changing it would
  require a second allocation for little benefit.
- **Server Region** — no such upstream concept was found in the Project
  Reclaimer documentation. Inventing one would violate the "do not invent
  upstream configuration keys" requirement, so it was left out.
- **Log Level / verbose flag** — upstream's `--verbose` CLI flag could not
  be reliably injected given this egg's "inherit upstream's CMD" startup
  mechanism (see README "Architecture decision"); see TROUBLESHOOTING.md.

## Networking

- **One Pterodactyl allocation is required.** Wings publishes that port for
  both `udp` and `tcp`; the game uses UDP, RCON (if enabled) uses TCP on
  the same port number, exactly matching upstream's own design.
- The server's `public_address` is left unset, so Project Reclaimer
  auto-detects it via an outbound request (to `api.ipify.org`) — this still
  resolves to the Wings node's real public IP even though the container
  itself is on an isolated bridge network, because outbound NAT preserves
  the host's public IP as seen by the destination.
- **UPnP is forced off.** Upstream only supports UPnP with host networking,
  which Wings does not use; port forwarding is Wings' job (it already
  publishes your allocation on the host).
- The container's own built-in "local master" (TCP 49175) is disabled
  (`RECLAIMER_DEDICATED_MASTER_ENABLED=false`). It would only ever list this
  one container's single server and would need its own extra allocation to
  be reachable externally — your server still reports itself to the public
  default master servers over its own game port regardless.
- **Multiple servers = multiple Pterodactyl server instances**, each with
  its own isolated storage (`/home/container`) and its own allocation. This
  egg does not use `RECLAIMER_DEDICATED_ONLY` (upstream's mechanism for
  running a subset of servers from one shared `dedicated.toml`) since each
  Pterodactyl instance already maps 1:1 to one Project Reclaimer server.

## RCON

- Disabled by default (`RCON_ENABLED=false`, empty password).
- When enabled, the console listens on `0.0.0.0` at the assigned port
  (required for it to be reachable through Wings' bridge networking /
  published allocation) rather than upstream's default `127.0.0.1`
  (which only makes sense with `network_mode: host`).
- **RCON is unencrypted** (per upstream docs). Treat the allocation's TCP
  side like any other admin interface: use a strong, unique password, and
  where possible restrict access at your firewall/security group to known
  admin IP ranges rather than relying on the password alone.
- To connect without exposing it further, use an SSH tunnel to the Wings
  node: `ssh -L 49176:127.0.0.1:49176 you@wings-node`, then point your RCON
  tool at `127.0.0.1:49176` — this only works if you also restrict the
  public-facing TCP port at the host firewall, since the port is still
  published by Docker for the game's UDP traffic.

## Playlists, maps, and mods

- Upload playlist files to `playlists/` in the file manager and reference
  them by path in the **Playlist** variable.
- Upload shared content (saved maps, game types, mods) to `content/Maps`,
  `content/Game Modes`, `content/Mods` respectively.
- Mods are **not** downloadable from Steam Workshop by this image (upstream
  has no Steam client inside the Docker image); copy mod folders in by hand
  as documented upstream ("Workshop downloads in Docker").

## Updates

- **Automatic Updates** (`AUTO_UPDATE`) lets Project Reclaimer itself
  update on start and hourly, per upstream's own mechanism. This does
  **not** update this Docker image or MCC/Halo 3.
- To move to a newer/older upstream release of the **image itself**,
  rebuild with a different `RECLAIMER_VERSION` build arg (see INSTALL.md)
  and change the egg's Docker Image field (or push the new tag over
  `latest` and have Wings re-pull it).
- Your `dedicated.toml`, playlists, bans, and uploaded assets are never
  touched by an image update — only `/home/container` is persistent, and
  neither install nor the entrypoint ever deletes existing files there.

## Backups and restoration

Use Pterodactyl's built-in server backup feature (backs up
`/home/container`, i.e. everything under `server/`, `content/`, uploaded
game assets, and `.cache`). Restoring a backup restores configuration,
bans, and uploaded content together; large Halo 3 game assets will make
backups correspondingly large — consider excluding `game/` from routine
backups if your backup storage is limited, since it can always be
re-uploaded from your own MCC installation.
