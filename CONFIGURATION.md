# Configuration Reference

## How configuration flows

An explicit console-manager override takes precedence for the managed server.
`server/.manager/overrides.json` stores selected playlist/settings; `configure.py`
validates it and writes those values into its managed `[[server]]` block on the
next container start, or when Configuration option 7 explicitly validates and
generates TOML before requesting RCON reload on .18+. Upstream per-server settings win over environment-supplied
defaults. Without manager state the existing Startup flow below is unchanged.
Configuration menu option 3 resets manager authority, with backup, for the next
start or explicit Apply. The server's actual reload reply determines timing;
saving JSON alone never proves live application. See [persistent configuration authority](CONSOLE-MANAGER.md#persistent-configuration-and-authority).

Most Project Reclaimer settings are controlled through its own documented
`RECLAIMER_DEDICATED_*` environment variables, which **override**
`dedicated.toml` at startup (upstream's own documented mechanism — see
[Environment variables](https://projectreclaimer.dev/host#config)). This
egg's [`docker/entrypoint.sh`](docker/entrypoint.sh) translates the egg
variables below into those environment variables every time the container
starts.

Two settings — a server's `name` and `port` — have **no** environment
variable override upstream, so [`docker/configure.py`](docker/configure.py)
writes them directly into `dedicated.toml`, but only inside a clearly
marked block:

```toml
# >>> PTERODACTYL MANAGED SERVER BLOCK (generated by configure.py; edits here are overwritten on every start) >>>
[[server]]
name = "..."
port = ...
# <<< PTERODACTYL MANAGED SERVER BLOCK <<<
```

**Most configuration outside that block is yours, except the `[rcon]` password and address fields, which are synchronized from Startup variables on each launch.** Edit `dedicated.toml` by hand
(via SFTP or the File Manager) for anything not covered by an egg variable
— custom `admins`, `[rcon]`/`[master]` tuning beyond what's exposed, etc.
Your edits are preserved across restarts and reinstalls.

## Egg variables

| Variable | Env var | Default | Maps to |
| --- | --- | --- | --- |
| Server Name | `SERVER_NAME` | `My Project Reclaimer Server` | `dedicated.toml` `[[server]].name` |
| Community Name | `HOST_NAME` | *(blank)* | `RECLAIMER_DEDICATED_HOST_NAME` (`host_name`) |
| Max Players | `MAX_PLAYERS` | `16` | `RECLAIMER_DEDICATED_MAX_PLAYERS` |
| Min Players | `MIN_PLAYERS` | `1` | `RECLAIMER_DEDICATED_MIN_PLAYERS` |
| Server Password | `SERVER_PASSWORD` | *(blank = open)* | `RECLAIMER_DEDICATED_PASSWORD` |
| Publicly Listed | `SERVER_PUBLIC` | `true` | `RECLAIMER_DEDICATED_HIDDEN` (inverted) |
| Playlist | `PLAYLIST` | *(blank)* | `dedicated.toml` `[[server]].playlist` |
| Map | `MAP` | *(blank)* | `dedicated.toml` `[[server]].map` (only if Playlist blank) |
| Game Type | `GAME_TYPE` | *(blank)* | `dedicated.toml` `[[server]].game` (only if Playlist blank) |
| Automatic Updates | `AUTO_UPDATE` | `false` | `RECLAIMER_DEDICATED_AUTO_UPDATE` |
| Enable RCON | `RCON_ENABLED` | `false` | gates whether RCON Password is passed through at all |
| RCON Password | `RCON_PASSWORD` | *(blank = disabled)* | `RECLAIMER_DEDICATED_RCON_PASSWORD` |
| Anti-Cheat | `ANTI_CHEAT` | `enforce` | `RECLAIMER_DEDICATED_ANTI_CHEAT` |
| Block VPN / Proxy | `BLOCK_VPN` | `true` | `RECLAIMER_DEDICATED_BLOCK_VPN` |

Pterodactyl's built-in `SERVER_PORT` (your assigned allocation) is used
directly for `[[server]].port`; there is no separate egg variable for it.

### Deliberately omitted variables

- **RCON Port** — not exposed. Upstream documents the console as listening
  on the *same* TCP port number as the game by default
  (`rcon_port` defaults to the game port), which is exactly what this egg
  relies on so only one Pterodactyl allocation is needed. Changing it would
  require a second allocation for little benefit.
- **Server Region** — no such upstream concept was found in the Project
  Reclaimer documentation. Inventing one would violate the "do not invent
  upstream configuration keys" requirement, so it was left out.
- **Log Level / verbose flag** — upstream's hosting docs mention a
  `--verbose` flag for the Windows `dedicated` CLI, but there is no
  confirmed equivalent for the Linux image's `reclaimer-entrypoint start`
  subcommand this egg invokes (its actual argument handling was read from
  the extracted entrypoint script, which takes no extra flags for `start`).
  Rather than guess at an unverified flag, this was left out; see
  TROUBLESHOOTING.md.
- **PUID / PGID** — present in upstream's Docker Compose docs, but inert
  under Pterodactyl: Wings always starts containers as an explicit,
  non-root UID/GID it controls itself (see README "How upstream's internals
  were verified"), and upstream's entrypoint only reads `PUID`/`PGID` when
  it finds itself already running as root, which never happens under
  Wings. Exposing them as egg variables would be misleading, so they are
  not present.

## Networking

- **One Pterodactyl allocation is required.** Wings publishes that port for
  both `udp` and `tcp`; the game uses UDP, RCON (if enabled) uses TCP on
  the same port number, exactly matching upstream's own design.
- The server's `public_address` is left unset, so Project Reclaimer
  auto-detects it via an outbound request (to `api.ipify.org`) — this
  *should* still resolve to the Wings node's real public IP even though the
  container itself is on an isolated bridge network, because outbound NAT
  normally preserves the host's public IP as seen by the destination. Public IP auto-detection was observed in live Wings logs, but remote
  reachability has **not** been confirmed — see
  TROUBLESHOOTING.md. If your server is not visible in the browser with its
  correct address, try setting it explicitly via a custom `dedicated.toml`
  edit outside the managed block, or via `RECLAIMER_DEDICATED_PUBLIC_ADDRESS`
  (not currently exposed as an egg variable; add it to the egg if needed).
- **UPnP is forced off.** Upstream only supports UPnP with host networking,
  which Wings does not use; Wings' own allocation system is what publishes
  your port on the Docker host, but **the Wings host's own OS firewall
  (and any upstream cloud/provider firewall or security group) still
  applies on top of that** and is not configured by this egg at all — see
  INSTALL.md and TROUBLESHOOTING.md for the exact commands to open the
  allocated port there. Do not assume a Pterodactyl allocation alone makes
  a server reachable from the internet.
- The container's own built-in "local master" (TCP 49175) is disabled
  (`RECLAIMER_DEDICATED_MASTER_ENABLED=false`). It would only ever list this
  one container's single server and would need its own extra allocation to
  be reachable externally — per upstream docs, servers report to the
  public default masters "either way", independent of this setting. Whether
  that registration actually succeeds end-to-end from behind Wings' bridge
  network (i.e. a player can find and join the server through the public
  Server Browser) has **not been verified against a live node** — see
  TROUBLESHOOTING.md.
- **Multiple servers = multiple Pterodactyl server instances**, each with
  its own isolated storage (`/home/container`) and its own allocation. This
  egg does not use `RECLAIMER_DEDICATED_ONLY` (upstream's mechanism for
  running a subset of servers from one shared `dedicated.toml`) since each
  Pterodactyl instance already maps 1:1 to one Project Reclaimer server.

## RCON and the interactive Pterodactyl console

- Submit `menu` (or `manager` / `console help`) to use numbered controls in the
  existing Console tab. Menu `exit` returns to raw RCON without stopping the game.
  `stop`/`quit`/Panel Stop retain graceful shutdown; raw `exit` outside the manager
  retains its previous shutdown-alias behavior. `rcon <command>` escapes from menus.
- Live RCON operations and persistent filesystem changes have independent
  backends. The latter save validated files and report restart requirements;
  editing a file does not imply the current game changed. See
  [CONSOLE-MANAGER.md](CONSOLE-MANAGER.md) and [CAPABILITIES.md](CAPABILITIES.md).
- Disabled by default. Set `RCON_ENABLED=true` and supply an 8–128 character
  `RCON_PASSWORD` in the server Startup variables to enable the console bridge.
- The current implementation binds RCON to **127.0.0.1 inside the container**
  on the same port number as the game (TCP for RCON, UDP for gameplay).
  It is **not** intended as a public TCP service. Never forward TCP RCON
  to the internet; open UDP for public gameplay as required.
- `docker/configure.py` synchronizes `[rcon].password` and `[rcon].address`
  in `server/dedicated.toml` on startup so the upstream `dedicated rcon`
  client can authenticate locally. Manual edits to these two keys are
  overridden; unrelated configuration is preserved.
- The `docker/console_bridge.py` process supervises the dedicated server,
  relays Pterodactyl stdin commands via `dedicated rcon`, prints responses,
  and forwards the Stop control to the server as SIGINT.
- Commands: `help`, `maps`, `modes`, `players`,
  `load Valhalla Slayer`, `load "The Pit" "Capture the Flag"`,
  `nextmap Guardian Slayer`, `help nextmap`, `vote`.
  Use `help <command>` for upstream command-specific guidance.
- Commands can be queued for the next lobby. The playlist ballot
  (`startvote playlist`) requires an **active playlist**. Other votes
  depend on player count and game state.
- Wings `v0.1.0-dev.3` live testing confirmed `maps`, `modes`,
  `players`, queueing `load`, graceful Stop and successful Start.
  The operator also reports WAN and multiple-client gameplay on the current
  installation. This branch needs a separate manager regression run.

## First boot and the Wine prefix

The very first time a given server starts, the entrypoint initializes a
fresh Wine prefix (`.wine-prefix/` under this server's storage) before the
game process can run — a one-time delay of roughly 10–60 seconds depending
on the node's hardware, during which the Panel will show the server as
still starting. This is deliberate: the Wine prefix baked into the upstream
Docker image belongs to a fixed build-time user ID that will not generally
match the user ID Wings assigns on your specific node, so this egg discards
it and builds one that matches, per server, on first start (see README "How
upstream's internals were verified"). Subsequent restarts reuse the
already-initialized prefix and do not pay this cost again, unless the
server's storage is wiped (e.g. a full reinstall).

## Playlists, maps, and mods

- The console Playlist Manager creates version-2 rotations without hand-writing
  JSON, validates inventory references, backs up edits and atomically saves files.
  Activate stores a pending override; explicit Apply/reload or startup generates
  TOML. It does not restart a match or get silently
  replaced by Startup PLAYLIST. Existing manual files and Startup selection still
  work when no explicit manager override is present.
- Vote images live in `server/content/Images/`. The content menu inspects uploaded
  files/mod metadata and changes `content/disabled-mods.json` with confirmation and
  backup. Restart after mod enable/disable/replacement and after playlist edits on
  0.9.13. On .20 active playlist edits may auto-reload from the next vote; the
  existing ballot/game is retained. No Steam or SteamCMD support is added.
- Upload playlist files to `server/playlists/` in the file manager and reference
  them by path in the **Playlist** variable.
- Upload shared content (saved maps, game types, mods) to `server/content/Maps`,
  `server/content/Game Modes`, `server/content/Mods` respectively.
- Mods are **not** downloadable from Steam Workshop by this image (upstream
  has no Steam client inside the Docker image); copy mod folders in by hand
  as documented upstream ("Workshop downloads in Docker").

## Updates

- **Automatic Updates** (`AUTO_UPDATE`) lets Project Reclaimer itself
  update on start and hourly, per upstream's own mechanism. This does
  **not** update this Docker image or MCC/Halo 3.
- To move to a newer/older upstream release of the **image itself**,
  rebuild with a different `RECLAIMER_VERSION` build arg (see INSTALL.md)
  and change the egg's Docker Image field (and publish a new immutable versioned image tag).
- Persistent files are retained across image updates. The existing managed TOML
  block and RCON fields are regenerated from current authority; unmanaged TOML,
  playlists, bans and uploaded assets are preserved. The upstream entrypoint
  refreshes its writable executable when the image's bundled hash changes.

## Persistent settings and reload (0.9.20+)

The version-1 overrides schema and version-2 playlist format are unchanged.
Guided keys are `friendly_fire`, `welcome` (empty clears), `voice_global`,
`voice_team`, `voice_proximity`, `load_timeout`, `trust_player_games` and `camera`.
Camera choices: `first_person`, `player_choice`, `third_person`; next multiplayer
game after reload. Campaign co-op/Firefight, vehicle views and modes with fixed
third-person cameras retain their own behavior.

Apply validates a private candidate using the actual native CLI against installed
assets before atomic TOML replacement, with backup and intervening-edit detection.
It then independently requests RCON `reload`. A rejected/unavailable reply is
reported as unconfirmed, not applied. Generated files remain saved; upstream's
own auto-reload may act separately. On .18+, upstream `auto_reload` defaults true;
the wrapper preserves administrator policy. Startup environment values are
captured at process launch, so changes there still require container restart.

| After confirmed reload | Settings |
| --- | --- |
| Immediate | host_name, password, max/min players, max_ping, load_timeout, welcome, admins, votes, voice/text, sharing/trust; name if data folder unchanged |
| Next game / next vote | friendly_fire, team_changing, camera / active playlist edits (current ballot/game retained) |
| Idle restart or container restart | ports/RCON, visibility, chat_log, VPN/anti-cheat, data-folder rename, content type/customization; campaign/ODST game settings can also idle-restart |
| Explicit container restart | mod replacement/enable/disable, Startup environment changes |

Password/port/path changes remain in Startup/admin files, not console prompts.
Clients must match 0.9.21 exactly. Automatic updates remain false by default.
Back up TOML/overrides before testing; restore both before returning to the .13
image, because its wrapper rejects new override keys. See
[the recorded rollback image and digest](UPSTREAM-0.9.20.md#preserved-rollback).

## Backups and restoration

Use Pterodactyl's built-in server backup feature (backs up
`/home/container`, i.e. everything under `server/`, `content/`, uploaded
game assets, and `.cache`). Restoring a backup restores configuration,
bans, and uploaded content together; large Halo 3 game assets will make
backups correspondingly large — consider excluding `game/` from routine
backups if your backup storage is limited, since it can always be
re-uploaded from your own MCC installation.
